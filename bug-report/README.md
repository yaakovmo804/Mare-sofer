# מראה סופר — דיווח תקלה בלחיצה

רכיב MVP עצמאי לדיווח תקלות מתוך האפליקציה.

## מה נשמר

- גרסת האפליקציה
- שם המסך הנוכחי
- הפעולה/הכפתור האחרון
- עד 10 פעולות אחרונות
- שגיאות `window.error`
- שגיאות `unhandledrejection`
- מצב חיבורים שמוזן במפורש על ידי האפליקציה
- הערה קצרה שהמשתמש מוסיף בזמן יצירת הדו״ח

## מה לא נאסף אוטומטית

הרכיב אינו קורא ערכי input/textarea, תוכן שיחה, שמות תלמידים, שמות קבצים או תמונות. מטרת ה־MVP היא אבחון טכני מינימלי ללא איסוף עודף.

## רכיבים

- `bug-report.js` — ליבת רישום האירועים והפקת הדו״ח.
- `widget.js` — לחיץ RTL קטן וחלון דיווח, עם allowlist ללחצנים מקצועיים בלבד.
- `demo.html` — הדגמה עצמאית.
- `v80-integration.html` — קטע שילוב מדויק למועמדת v81 על בסיס קוד v80 הקנוני.
- `tests/bug-report.test.mjs` — בדיקות יחידה לליבה.

## שלושת סוגי התקלה הראשוניים

1. תקלה בממשק — לחצן, תפריט, חלון, ניווט.
2. תקלה בחיבור — Notion/API/מודל/שרת.
3. תוצאה שגויה — הפעולה הושלמה אך התוצאה המקצועית או החזותית אינה נכונה.

## עקרון MVP

בשלב הראשון אין צילום מסך אוטומטי, העלאת לוגים לשרת או הקלטת session. קודם בודקים האם דו״ח מקומי קצר עם רצף פעולות פותר בפועל את בעיית שחזור התקלה.

## מצב המקור והחסם הנוכחי

האתר הפעיל של „מראה סופר — טעימה ראשונה” נמצא ב־Sites בגרסה 80. Library חושפת את ה־Site projection ואת מספר הגרסה, אך לא את קובצי המקור/ZIP של v80, ומאגר GitHub אינו המקור הקנוני העדכני של האתר.

לכן אין למזג את ה־PR אל `main` הישן. השלב הבא הוא לקחת את קוד המקור הקנוני של v80, להוסיף אליו את שני הקבצים `bug-report.js` ו־`widget.js`, להפעיל את `v80-integration.html` במסך „שיחה” בלבד, ולשמור כמועמדת v81 לפני פריסה.
