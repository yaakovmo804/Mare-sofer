# מראה סופר — דיווח תקלה בלחיצה

רכיב MVP עצמאי לדיווח תקלות מתוך האפליקציה.

## מה נשמר

- גרסת האפליקציה
- שם המסך הנוכחי
- הפעולה/הכפתור האחרון
- עד 10 פעולות אחרונות
- שגיאות `window.error`
- שגיאות `unhandledrejection`
- מצב חיבורים שמוזן במפורש על ידי האפליקציה
- הערה קצרה שהמשתמש מוסיף בזמן יצירת הדו״ח

## מה לא נאסף אוטומטית

הרכיב אינו קורא ערכי input/textarea, תוכן שיחה, שמות תלמידים, שמות קבצים או תמונות. שכבת `widget.js` עוקבת רק אחרי לחצנים שנמצאים ברשימת allowlist מקצועית מפורשת.

## שילוב מינימלי בגרסה 80

```html
<script src="/bug-report/bug-report.js"></script>
<script src="/bug-report/widget.js"></script>
<script>
  MarehSoferBugReportWidget.init({
    version: 'v80',
    screen: 'שיחה',
    sourceStatus: {
      OpenAI: 'תקין',
      Claude: 'תקין',
      'מאגר מקומי': 'מוכן',
      Notion: 'מקומי בלבד'
    }
  });
</script>
```

ה־widget מוסיף לחיץ קטן „דווח תקלה” ופותח חלון RTL מקומי. המידע אינו נשלח לשרת; המשתמש מעתיק את הדו״ח ומדביק אותו בשיחת הפיתוח.

## API בסיסי

```js
const bug = window.MarehSoferBugReport;
bug.setVersion('v80');
bug.setScreen('שיחה');
bug.setSourceStatus('Notion', 'מקומי בלבד');
bug.control('מקרה מקביל');
bug.error('Notion request failed', { source: 'notion-bridge' });
```

## שלושת סוגי התקלה הראשוניים

1. תקלה בממשק — לחצן, תפריט, חלון, ניווט.
2. תקלה בחיבור — Notion/API/מודל/שרת.
3. תוצאה שגויה — הפעולה הושלמה אך התוצאה המקצועית או החזותית אינה נכונה.

## עקרון MVP

בשלב הראשון אין צילום מסך אוטומטי, העלאת לוגים לשרת או הקלטת session. קודם בודקים האם דו״ח מקומי קצר עם רצף פעולות פותר בפועל את בעיית שחזור התקלה.

## שער שילוב בטוח

האתר הפעיל של „מראה סופר — טעימה ראשונה” נמצא ב־Sites בגרסה 80. ספריית ChatGPT חושפת את האתר הפעיל ואת מספר הגרסה, אך Site projection אינו ניתן ל־materialize לקוד מקור; GitHub אינו המקור הקנוני העדכני של האתר.

לכן ה־PR נשאר Draft ואסור למזג אותו ל־`main` כתחליף לגרסה 80. השלב הבא הוא לקבל את קוד המקור הקנוני של v80, להוסיף את שני הקבצים, להפעיל את ה־widget במסך אחד בלבד, ולבדוק תקלה אמיתית לפני הרחבה לכל האפליקציה.
